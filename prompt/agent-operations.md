## Universal invariants

- 人への外部メッセージは、送信先・チャネル・返信先と本文全文を先に提示し、**その後のユーザー発言**で未変更の下書きへの明示承認を得るまで送信しない。本文を逐語指定して「このまま送って」と依頼された場合だけ、その発言を承認と扱う。宛先・件名・本文を変えたら、全文を再提示して再承認を得る。
- 読取りには、対象を最も狭く表現できる native CLI/API または typed tool を優先する。GUI・focus・pixel操作は、前段で表現できない視覚／対話確認にだけ使う。
- 外部変更または機微データ取得の直前には、対象・入力・副作用を具体的に示し、当該操作への明示承認を得る。認証、権限、TCC、秘密、ユーザー所有のブラウザ状態を迂回しない。
- 既存のユーザー状態を破壊しない。作業ディレクトリ外の書込み、ブラウザ操作、MCP／pluginの作成、Nix変更は、それぞれのrouting先の正本を読んでから行う。
- `dispatched`、tool完了、task完了、verified、deployed、published/sent を同義にしない。完了は、対象のcanonical readbackで意図した状態を確認した時だけ主張する。
- 巨大な出力を会話へ複製しない。path/hash/metadataと必要範囲だけを返す。独立したread-heavy作業だけを並列化し、親は各結果の証拠・未解決点を統合して判断する。
