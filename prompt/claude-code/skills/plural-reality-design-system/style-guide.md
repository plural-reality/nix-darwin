# 表記規約（多元現実の対外文書・Web・資料）

対象は HP、プロダクトの LP、営業資料、報告書、ホワイトペーパー、書籍原稿の地の文、メール署名。
機械的に検出できる誤りは `scripts/brand-lint` が検出する（末尾の対応表）。
書籍は各 repo の style-guide を優先し、このファイルと矛盾する箇所はその repo で理由を書く。

出典: `_brand-unification-2026-10-01/DECISIONS.md`（A4, A5, C1, C2, C3, D1）と `02-hp-copy.md` 末尾の用語集。

## 1. 会社名（A4）

| 文脈 | 書き方 |
|---|---|
| 和文の法人名（署名・発信者・契約・奥付・お知らせ末尾） | **合同会社多元現実**（スペースなし） |
| 英文の法人名 | **Plural Reality LLC** |
| 和文本文中の略称 | 多元現実 |
| 英文本文中の略称 | Plural Reality |
| 和文で英名を併記する初出（正式紹介の1回だけ） | 多元現実（Plural Reality） |
| 著作権表示（和文・英文とも） | `© 2026 Plural Reality LLC`（年は発行年） |
| 共同著作 | `© 2026 一般社団法人構想日本／Plural Reality LLC` のように「／」で併記 |

- 誤り: 多元現実合同会社、合同会社 多元現実、(同)多元現実、多元現実社、Plural Reality Inc.、Plural Reality, Inc.、plural reality llc、PluralReality。
- 「弊社」はプレスリリース調のお知らせだけで使う。サイト本文・活動記録は「多元現実」か「私たち」。「当社」は使わない。
- 適格請求書発行事業者の登録番号は © に混ぜない。奥付の会社情報欄に置く。
- 代表者の肩書き（「代表社員」「代表」「CEO」のどれを使うか）は TODO(要確認)。決まるまでは既存の HP 会社概要の表記に合わせ、新しい表記を作らない。

## 2. 製品名（A5）

対外製品名は2つだけ。

| 和文 | 英文 | 備考 |
|---|---|---|
| **倍速会議** | **Baisoku Kaigi** | 千人会議・倍速商談・マンション版は製品名ではなく「倍速会議の活用シーン」として書く |
| **倍速アンケート** | **Baisoku Survey** | |

- Cartographer（倍速会議）と Sonar（倍速アンケート）は社内コードネーム。対外文書・UI 文言・テックラベルに出さない。URL・識別子・リポジトリ名は対象外。
- 使わない: 深掘りアンケート、Baisoku Enquête、倍速ｱﾝｹｰﾄ（半角カナ）、ばいそく会議、倍速会議（Cartographer）のような併記。
- 退役・削除済み（C3）: 議員AI秘書、議員秘書、「議員支援」ラベル。新しい文書に書かない。
- 一行定義（説明句の揺れを止める）: 倍速会議＝「会議の前と最中に参加者の考えを集め、合意点・対立点を可視化するAI合意形成ツール」。各ページはこの定義のあとに文脈に合う機能を足す。
- 製品の正規 URL は製品ごとに1つ。決定は TODO(要確認)（`app.baisoku-kaigi.com` と `baisoku-kaigi.com` などが混在している）。`*.vercel.app` やプレビュー URL（`.preview.` を含むもの）は対外文書に載せない。太田市レポートのように意図してプレビューを出す場合は本文に「プレビュー版」と明記し、lint の allowlist に登録する（B4）。

## 3. 日付・期間

| 用途 | 書き方 | 使わない |
|---|---|---|
| 和文本文・表紙・奥付 | `2026年10月1日` | 2026/10/1、2026.10.1、2026.03（ラベル表記） |
| 範囲 | `2025年9月〜12月`、`2025年9月〜2026年4月`（全角「〜」、前後に空白なし） | `2025年9月 〜 12月`、`2025年9月~12月` |
| 英文 | `October 1, 2026` | 1 Oct 2026 と混在させない |
| データ・メタ情報・ファイル名・ログ | ISO `2026-10-01` | |
| 期間の長さ | `8か月` | 8ヶ月、8カ月 |

- 一次記録（事例の詳細ページ・議事録）と日付が食い違うときは一次記録に合わせる（C2）。例: DD2030 の会は 2026年1月10日。

## 4. 数値と出典

- 数えられる実績（自治体数・参加者数・意見数）だけを実数で書く。満足度・短縮率など出典のない率は書かない（C1）。
- 4桁以上は桁区切り `1,000`、`10,000人`。和文で大きな数は `1万人` も可。1つの文書で混ぜない。
- 見出し・数量の強調は算用数字（`3つのステップ`）。和語の「一つひとつ」「ひとつの」はそのまま。
- 単位は数字に詰めて書く（`30年`、`95人`）。延べ人数は「のべ95人」。
- 数値には出典を付ける。図表の直下に1行で書く。
  - 外部資料: `出典：総務省「○○調査」（2025年）`
  - 自社の実測: `出典：多元現実調べ（2026年3月、対象と算定条件）`
- 時点で変わる数値（実績回数・登録者数）は時点を書く: `356回（2026年2月時点）`。

## 5. 図表

- 番号は文書内の通し番号。`図1`、`表1`。
- キャプションは「図1　タイトル」（番号とタイトルの間は全角スペース1つ、体言止め、句点なし）。
- 図のキャプションは図の下、表のキャプションは表の上。出典行はその直後。
- 本文から番号で参照する（「図1のとおり」）。「下図」「上の表」は使わない。
- チャートはモノクロ。色だけで系列を区別しない（線種・塗り・直接ラベルで区別する）。アクセント色をチャートに入れない。

## 6. 機密区分・免責

機密区分は3段階。表紙右上と奥付に同じ表示を置く。英字の `CONFIDENTIAL` は使わない。

| 区分 | 表示 | 使う場面 |
|---|---|---|
| 社外秘 | `社外秘` | 社内レビュー用の草稿 |
| 先方限り | `先方限り（○○市 ご担当者さま）` | 自治体・企業への提案や報告 |
| 公開 | 表示なし | HP・プレスリリース・公開レポート |

定型の免責文（必要な文書だけ。文脈に合わない免責は付けない）:

- 試算・シミュレーション: `本資料の数値は試算であり、実際の結果を保証するものではありません。`
- 参考ツール: `本ツールは参考用です。正式な判断は○○の決定に基づきます。`
- 公開情報の分析: `本資料は公開情報に基づき多元現実が作成した分析です。`

## 7. 文体と記号

- 営業・報告資料はです・ます。書籍・論考はである。見出しと図表キャプションは体言止め。
- 和文中の括弧・コロン・感嘆符・疑問符は全角 `（）：！？`。英字だけの括弧内も全角括弧で囲む。
- 和欧間にスペースを入れない（`AIが`、`Mozilla Foundationの`）。
- 三点リーダーは `…`。`...` は使わない。
- 半角カナは使わない（lint で検出）。
- 本文の人名は姓名の間にスペースを入れない（`前田真氏`）。
- 和文に斜体を掛けない（合成斜体になる）。強調はウェイトか下線。
- 英字ラベルは固有名詞・略語に限る。`CASE STUDY`、`Executive Summary` のような英語の見出しラベルは日本語にする。
