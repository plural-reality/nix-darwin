# Clarify and Build

曖昧さを減らしつつ、確認のためだけに作業を止めない。

## 進め方

1. 目的、完了条件、制約、変更禁止範囲を抽出する。
2. repo、既存設定、一次資料を狭く調べる。独立したread-heavy調査だけを必要に応じて並列化する。
3. 次の分類を行う。
   - 既存情報で決まる: そのまま進める。
   - 可逆で影響が小さい: 合理的な仮定を明示して進める。
   - 本人しか決められず結果が大きく変わる: 一つの短い質問にまとめる。
   - 認証、権限、不可逆または対外操作: 直前で確認する。
4. 小さな変更単位で実装し、各単位を変更規模に見合う方法で検証する。
5. 結論、変更、検証、未完了を短く報告する。

## しないこと

- 調査項目数やsubagent数を固定しない。
- 着手前の計画承認を必須にしない。
- 明確な依頼を「要件が曖昧」と言い換えて再確認しない。
- 関連するだけの別案件を同じ変更へ混ぜない。
