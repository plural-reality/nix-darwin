# 下書きを送信後に残さない

Gmail の下書きは `draftId` で管理する。`messageId` は編集・送信で変わるため、固定の下書きIDと取り違えない。
Gmail の `drafts.send` は元の下書きを消費する。一方、別のメールとして SMTP/API から送ると元の下書きが残り得る。Apple Mail など別クライアントで本人が送った場合も、送信済みと下書きをそれぞれ確認する。

## 作成と編集

- 作成前に、そのアカウントの既存下書きを調べる。同じ用件の下書きがあれば本文・宛先・添付を読み、編集対象のIDを確定する。件名一致だけで同一視しない。
- 編集は既存の `draftId` に対する `drafts.update` を使う。修正版を `drafts.create` / `+reply --draft` で増やさない。
- 編集直前に読み戻して本人の変更を保つ。保存後も同じ下書きIDから再取得し、宛先・件名・本文・添付と最新の `messageId` を確認する。
- タイムアウトや空の出力は作成失敗の証拠ではない。再作成の前に下書きを照合する。
- 引き渡しにはアカウント、`draftId`、最新の `messageId`、返信元 `threadId` を作業記録に残す。秘密値や不要な本文をログに残さない。
- 本人が送る場合は、その保存済み下書き自体を開いて渡す。別の新規メールや返信欄へ本文をコピーして引き渡さない。

## 承認後の送信

宛先・Cc・Bcc・件名・本文全文を提示し、その後のユーザー発言で未変更の案への明示承認を得る。添付や返信先も確認する。下書き作成や修正の依頼は送信承認ではない。

- 既存のGmail下書きを送るときは、承認済みの `draftId` を `drafts.send` に渡す。同じ本文を `messages.send` / `+send` / `+reply` / SMTPへ再構成して送らない。
- 法人の呼出し例（IDは直前に読み戻して確認した実値に置換）:

```sh
gws gmail users drafts send --params '{"userId":"me"}' --json '{"id":"DRAFT_ID"}'
```

- 個人で利用するCLIが既存下書きの消費を保証しない場合、Gmailの保存済み下書きを本人に開いて渡す。`himalaya template send` だけで元下書きが消えたとは扱わない。
- 送信がタイムアウトしたら、送信済みと下書きを照合するまで再送しない。下書きが残っているだけでは送信失敗の証拠にならない。

## 送信後の確認と残留整理

エージェントが送信した直後、本人から送信したと報告されたとき、または同じ用件を再開するときに確認する。

1. 送信先アカウントの送信済みメールを読み戻し、`SENT` と宛先・本文・添付・返信先を確認する。下書きが消えただけでは送信成功としない。
2. 下書き一覧を再取得し、元の `draftId` と同じ用件の別下書きが残っていないか確認する。UIのスレッド表示だけで判定しない。
3. 残っている場合は、送信済みと下書きの From/To/Cc/Bcc、件名、本文の各MIME表現、添付内容、返信先、日時を照合する。本文の比較で無視してよいのはCRLF/LF等の改行形式だけ。空本文の一致、件名一致、類似度だけで整理しない。送信後に作られた下書きは別の用件の可能性があるため自動整理しない。
4. 本依頼で整理が許可された、送信済みと完全に同じ重複のみ、対象 `messageId` を直前に再取得して `messages.trash` でゴミ箱へ移す。`drafts.delete` による完全削除を既定にしない。権限が未確認なら具体的な対象を提示して承認を得る。
5. 本人の編集が入った旧版、宛先や添付が異なる版、後続の新しい返信は、差分を提示して本人が不要と判断するまで残す。「送信済みだから全部削除」としない。
6. 処理後に下書き一覧・退避対象の `TRASH`・送信済み原本の `SENT` を再取得する。Gmailのゴミ箱は永久保管ではない。下書きが再び現れた場合は、クライアントで開いた編集画面等を確認し、削除や再送を繰り返さない。

これはメール作業時の確認手順であり、無断の常駐監視・定期削除・アカウント設定変更は追加しない。

参照: [Gmail下書きの作成・更新・送信](https://developers.google.com/workspace/gmail/api/guides/drafts)、[messages.trash](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages/trash)。
