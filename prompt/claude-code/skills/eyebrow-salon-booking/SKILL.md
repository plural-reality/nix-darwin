# 眉毛サロン予約

予約サイト、確認メール、Apple Calendar を別々の推測源にせず、予約完了を唯一の確定入力として予定へ変換する。

## 既定値

- 店舗指定がなければ、直近の利用店舗を候補にする。プラスエイト渋谷店が明示された場合は公式の Live Members 予約導線を使う。
- 担当者の希望がなければ「指名なし」。価格、所要時間、割引期限は予約時点の公式画面で確認し、固定値として覚えない。
- Safari の既存ログイン状態と保存済みパスワードのオートフィルを優先する。パスワードの値は読み出し・表示・保存しない。Touch ID、端末パスコード、OTP、CAPTCHA が必要なら本人に委ねる。

## 手順

1. 予約履歴または予約確認メールから最終来店日を確認する。
2. 公式予約画面で、最終来店日から利用できるリピーター割引と期限を確認する。
3. Apple Calendar の本人用カレンダーだけを読み、施術時間と移動時間を含めて候補を出す。共有相手の予定は空き判定に使わない。
4. ユーザーが選んだ日時・店舗・メニューについてのみ予約を確定する。
5. 完了画面と予約確認メールの両方から、日時・メニュー・料金・担当・店舗を読み戻す。どちらも確認できない限り完了扱いにしない。
6. `apple-calendar` スキルの `evkit calendar` だけを使い、iCloud の本人用カレンダーへ登録する。

## カレンダー契約

- 施術イベントには店舗名と完全な住所を構造化位置情報として必ず入れる。概要欄の住所だけで代用しない。
- 出発地点は、ユーザーの明示、または直前予定の構造化位置情報から決める。予約日と出発地点を説明した曜日が一致しない場合は、実際の予約日を明示してから適用する。
- 公共交通機関の乗車時間だけでなく、駅構内移動、待ち時間、店舗までの徒歩、遅刻回避の余裕を含める。
- 現行の `evkit` にネイティブ travel time 入力がない場合は、施術開始時刻までの独立した移動イベントとしてブロックする。タイトルは `移動｜<出発地> → <店舗>`、位置情報は到着店舗にする。
- 施術イベントの概要欄に、必ず次の2行を入れる。

```text
ChatGPT（Codex）が予約。
元セッション: https://chatgpt.com/codex/tasks/<threadId>
```

- `<threadId>` は利用可能なら Node REPL の `nodeRepl.requestMeta.threadId` から取得する。推測したIDや別タスクのURLを入れない。
- 移動イベントにも同じ元セッションURLを入れる。
- カレンダー更新後は、日時、概要、位置情報、移動ブロックを Apple Calendar から読み戻す。

## 安全境界

- 候補提示前に予約を確定しない。ユーザーが具体的な候補を選んだ後の確定操作は、その予約について承認済みとして進める。
- キャンセル、日時変更、メニュー変更、担当変更は新しい外部副作用なので、明示依頼なしに行わない。
- ログイン情報、会員番号、確認メール内の個人情報を回答やカレンダーへ転記しない。
