# 外部支援者・自治体協働への応用

以下はスキル独自の応用。特定の自治体・関係者の現状についての事実認定ではない。
音威子府を含む実案件で使うときは、その時点の依頼・合意・活動記録を確認し、過去の分析を診断の結論にしない。
共有スキルに、個人名、会話本文、未公開の案件状態を埋め込まない。

## 最初に区別する関係

発注者、受入窓口、決定責任者、実務担当者、影響を受ける住民・利用者は同じとは限らない。
窓口の好意的な返事だけで、担当課の負担引受けや組織の方針変更が合意されたとはしない。
責任者が複数なら、どの判断に誰が必要なのかを案件の範囲で確認する。

## 状況ごとの相談例

### 「まずAIのデモを作って持っていく」

デモの目的が、需要の確認、業務の理解、関係者の共通理解、本番導入の判断のどれかで、作るものは変わる。
重要な論点だけを選んで返す。

> デモを作るのは進められます。今回は、見栄えより「誰のどの作業を試すか」が判断を分けそうです。実際の担当者が一つの入力を処理し、手作業との差を確かめられる形に絞る案です。

公開・本番データ利用などを、この例から許可されたと扱わない。

### 「評判はよいが、その先に進まない」

価値がない、優先順位が低い、時間がない、責任が曖昧、運用負担が増える、意思決定の時期が違うなど、複数の説明を保つ。
説得不足と決めつけず、依頼・試行・導入のどの段階なのかを確認する。

> 関心は確認できていますが、実務に載せる条件は別に残っているかもしれません。追加説明の前に、小さな試行を誰が担当できるか、または今は試さない理由を確かめると、次に作るべきものが変わります。

### 「もっと成果を出さないといけない」

本人の焦りと、相手が求めた期限・成果を区別する。未合意の仕事を増やして信用を買う案にしない。
期限が既に決まっているなら、学習期間の名目で延ばさず、最低限の約束を守る案を作る。

## 小さな計画の型

必要な場合だけ、次の項目で一つの試行を組む。全部を埋めるために本人へ質問しない。

| 項目 | 決める内容 |
|---|---|
| 目的 | 誰のどんな困りごと・判断を扱うか |
| 確かめる仮説 | なぜ現在進まないのか。別の説明は何か |
| 合意 | 判断する人、作業する人、使える時間・資源 |
| 行動 | 現場観察、短い面談、既存手順の試行など、最小の確認 |
| 証拠 | 使用実績、担当者による確認、処理時間など、目的に適した観察 |
| 振り返り | いつ、何を見て継続・変更・中止を決めるか |

例: 「資料を一本作る」は活動。「その資料を担当者が判断に使えた」は結果の候補。
ただし、納品そのものが合意された目的である仕事を、勝手に導入や制度変更の責任へ拡張しない。
自治体の信頼や住民利益を、一つの数値や一人の賛成だけで代表させない。
