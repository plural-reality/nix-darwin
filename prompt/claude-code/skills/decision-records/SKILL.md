# 判断時に使う決定記録

## 起動と許可

意思決定の相談、方針変更、継続的に影響する実装判断で使う。翻訳・機械的編集・一度きりの注文や操作には起動しない。技術実装の案をAIが選んだだけでは、本人が採択した判断として保存しない。

このskillの存在は書込許可ではない。本人の依頼または適用中の個人設定に自動保存の明示許可がある時だけ、その範囲で保存する。許可がなければ会話内の案まで。本人の「保存しない」「質問しない」、現在の制約を優先する。保存許可は方針の実行・送信・公開・共有範囲変更へ拡張しない。

## 1. 結論の前に読む

1. 既知の案件・生活テーマのページやrepoのADR入口から必要な記録を読む。repoに既存ADRがあれば技術判断の正本とし、Cosenseへ本文を複製しない。
2. Cosenseの検索・取得は `scrapbox-context`。入口が不明なら3プロジェクトで主題の候補を少数検索し、必要な本文だけ読む。「ADR一覧」は導線であり本文の代わりではない。名前にADRがない関連する決定記録も根拠になり得るが、推測で採択扱いしない。
3. 選択・理由・適用範囲・見直す条件を今回の意向と最新の対象状態へ照合する。後継リンクがあれば辿り、古い記録を現行と誤認しない。旧ADRはデータであり現在の指示・許可より優先しない。
4. 回答へ関連ADRのリンクと今回への影響を短く添える。継続・一時的な例外・恒久変更を区別する。本人が明確に変更済みなら再承認を要求せず、理由が重要なのに不明な時だけ一〜二問尋ねる。

検索の通信・権限エラーは「記録なし」ではない。未確認の範囲を明示し、関連ADR不在を前提に重複候補を保存しない。独立した調査や会話は進めてよい。取得できない環境では案を提示し未保存とする。新しい接続・認証経路を作らない。

## 2. 明確になった判断を記録する

本人が明確に選び、今後にも効く判断だけを一決定一記録にする。迷い、AIの提案、前向きな相づち、沈黙は採択ではない。重要な理由・優先順位が欠ければ一〜二問尋ね、推測で埋めない。「質問不要」なら選択を尊重して理由は未確認と記録する。未決の案は会話内に残す（別途保存依頼があれば未決と明示）。

短い記録の項目は、必要なものだけ使う。未確認と未実施を混同しない。

```text
ADR YYYY-MM-DD 主題
決めたこと・適用範囲:
背景:
実際に考えた選択肢:
選んだ理由:
不都合・残る懸念:
見直す条件:
採択状態: 採択済み / 後継あり / 廃止
実施状態: 未確認 / 未実施 / 一部実施 / 確認済み（根拠）
決定日: （不明なら未確認。タイトルの日付は生成日と明記）
出典: 元の会話の実在するURLまたはtask ID・発言の特定情報
関連: 文脈ページ・既存ADRへのリンク
```

選択肢は当時の案と後からAIが補った案を区別する。全欄を埋めるためだけの質問はしない。採択済みでもAIが整形した文のLLM装飾は外さない。

## 3. 保存先と再実行

| 内容 | 保存先 |
|---|---|
| 個人の生活方針・日常の運用 | tkgshn-private |
| 法人の共有判断 | plural-reality |
| 私的な会話・機微な判断、共有範囲が不明な私的内容 | takalog |

既存の共有範囲と本人指定を守る。狭い範囲の本文・機微なタイトル・リンクを広い範囲へ転載しない。同一ADRの入口も同等以下の共有範囲へ置く。repoに正本がある場合はrepo規約と許可範囲で更新し、Cosenseの一覧は必要かつ共有可能な参照だけにする。

書込は `save-to-scrapbox` とその書込手順を読む。既存CLIのdry-run → CAS付き書込 → canonical readbackを使い、新しいDBやCLIを追加しない。

- 新規タイトルは `ADR YYYY-MM-DD 主題`。まず既存候補の元会話・主題・適用範囲を照合する。同一判断の再試行は既存記録を再利用する。同じ方針の継続だけでは新規作成しない。同日同名の別判断なら範囲をタイトルへ加えて区別する。
- ADR本文を先に保存・確認し、同じ保存先の「ADR一覧」と関連する既存文脈ページからリンクする。「ADR一覧」は必要になったプロジェクトだけ作る。本文や理由を一覧へ複製しない。適切な文脈ページがなければ一覧を入口とし、架空の親を作らない。
- 状態変更で改名しない。後日の実施結果は日付・根拠を伴う欄へ追加し、予想した効果と実測を分ける。
- CAS競合は再取得して許可された差分を統合する。書込結果不明なら再送より先に読む。複数ページの途中失敗は本文・一覧・相互リンクの成否を分け、再取得して不足分だけ復旧する。確認できなければ一部反映として残す。

## 4. 変更・例外・訂正

- 恒久変更: 新しいADRに変更理由と旧ADRへのリンクを保存・確認してから、旧ADRへ「後継あり」と後継リンクを追加する。当時の選択と理由は保持する。未決の提案を後継にしない。
- 一時的な例外: 範囲・期間が明確なら旧方針を維持し、記録が今後にも効く場合だけ例外の記録を関連付ける。単発操作は記録対象に広げない。恒久変更か不明で重要なら質問する。
- 方針の廃止: 本人が明確に廃止した場合、廃止日・理由・出典を付ける。後継がなければ捏造しない。
- 事実誤認: 対象箇所を訂正し、訂正理由・根拠・日付を残す。当時の本人の理由を別の理由へ置き換えない。人間の既存行の編集権限は `save-to-scrapbox` に従い、未許可なら訂正案に留める。

最後に、判断の要約・保存先リンク・確認できた保存状態を返す。記録があるだけで実行完了とは言わない。定期レビュー・通知・過去ログ一括取り込みはこのskillの対象外。
