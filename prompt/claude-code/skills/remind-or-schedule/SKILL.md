# remind-or-schedule — 何を、誰が、何を契機に行うか

実際の書込みは既存の各バックエンドへ委譲する。予定の存在、本人の対応責任、対応完了は別物。
他人が対応するものや待ち状態を、本人向けTODOへ自動で増やさない。表示ラベルやComputer Historyは候補であり、最新の会話・対象サービスで照合する。

## まずイベントかタスクか

| 意図 | 保存先 |
|---|---|
| 特定日時に起こる／拘束される会議・予約・訪問・開館枠 | Calendar。`apple-calendar` へ |
| 提出・返信・支払い等、終えたらチェックするやること | Apple Reminders。締切があってもCalendarの「締切イベント」にしない |
| 本人の行動でなくエージェントが継続確認・再開する仕事 | Codex automationの公式管理tool。本人向け確認TODOを量産しない |

本人が明示して時間ブロックを確保したい場合のみ、タスクの作業枠をCalendarに置く。タスク自体の締切と混同せず、二重作成を暗黙に行わない。

## アカウント・リスト

- 会社のイベント → 本人の法人Google Calendar。`apple-calendar` の法人分岐（`gws calendar`）。
- 個人のイベント → 本人指定の既存iCloud Calendar。名前で決め打ちせずcatalogでIDを確認。
- 会社のタスク → 既存 `多元タスク` リスト。
- 個人タスク → 日付で再浮上するなら `その時が来たらやること`、今日中の緊急なら `直近でやること`、場所発火なら `ある場所に居る時にやること`。
- 本人が別の保存先を明示した場合はそれを優先し、現在のリストを確認する。既定の `Everything` へ黙って流さない。

## タスクの発火条件

- **日時・期日**: 真の締切と通知希望日時を別に保持する。単発期日、繰返し、追加通知は利用する `evkit reminders.*` の実schemaを確認して選ぶ。`reminders.ensure` はmarker付き1件の冪等作成だけで、期日・通知を設定する機能はない。未対応の日時項目を付けて「登録済み」とせず、登録可能な範囲と未完了を分ける。締切を通知日にすり替えない。
- **特定地点に着いたら**: `apple-reminders-geofence` へ。目的地・座標・半径・`proximity=enter`・上記の明示リストを渡す。同じ徒歩圏の候補はnotesにまとめ、通知を量産しない。
- **カテゴリのどこかに近づいたら**: geo-reminderアプリの領域。多数の地点を無理に固定ジオフェンスへ展開しない。現在の対応・稼働・投入経路を確認し、アプリへの実投入をせずに完了としない。新しい連携の実装・DB書込はこの振り分け依頼から広げない。

時間が書かれていてもタスクをCalendarへ優先しない。旅程の到着日と「次にオフィスへ行く時」のような行動条件を取り違えない。
日時と場所の両方を希望した場合のみ両条件を扱う。特定地点が多数の場合の上限・半径・運用は `apple-reminders-geofence` に従う。

## 完了条件

承認範囲の対象だけを、上で選んだ既存バックエンド（`evkit` / 法人 `gws calendar` / Codex automation）で重複なく書き、正本を再取得して対象・内容・期日／通知または位置条件を照合する。
markerで置き換える時は未完了の一致対象だけ。完了履歴と無関係な予定は保持する。Calendarのsource、Remindersのリスト、通知が端末で実際に発火したことは別々の確認である。
許可不足や機能不足を直接Swift・osascriptや別サービスへの無断代替で回避しない。重大な曖昧さだけを本人へ確認し、通常の振り分け・可逆的な準備は続ける。
