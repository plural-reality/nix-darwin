# Scope Guard

一つの変更単位を一つの目的と検証へ結びつける。

## 判定

同じ単位に残すのは、次をすべて満たす変更。

- 同じユーザー目的に必要
- 同じレビュー文脈で理解できる
- 同じ検証で安全性を説明できる
- 一方だけをrevertする必要が低い

満たさない差分は、既存変更を破壊せず別branch、別commit、または別task候補として記録する。

## 手順

1. `git status` と対象差分を読み、ユーザー既存変更を識別する。
2. 今回の目的に直接必要なpathだけを所有範囲にする。
3. 偶発的に見つけた問題は、今回の完了を妨げない限り修正へ混ぜない。
4. 分割が必要なら、現在の安全な単位を先に完了し、残りを短い候補として示す。
5. commit/PR前に、差分・テスト・目的が一対一で説明できるか確認する。

会話の長さだけを理由にspin-offを要求しない。
