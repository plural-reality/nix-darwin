# Best Practices Research

目的は情報量ではなく、現在の判断を改善すること。

## 手順

1. 依頼から、決めること・制約・既に分かっていることを一文ずつ抜き出す。
2. 時点で変わる事実や不確かな論点だけを検索する。技術事項は公式文書・一次資料を優先する。
3. 通常は1〜3個の検索観点から始め、判断を支える十分な一致または有力な相違が見えたら止める。
4. 既存実装やユーザー固有の制約と照合し、そのまま使える点と使えない点を分ける。
5. 依頼が変更まで含むなら、承認済みの範囲で反映し、規模に見合う検証を行う。

## 出力

- 結論
- 現在の作業に採用する点
- 採用しない点と理由
- 重要な一次資料へのリンク
- 未確認事項（ある場合のみ）

固定数の検索、網羅目的の第三者記事収集、長い事例カタログは要求しない。
