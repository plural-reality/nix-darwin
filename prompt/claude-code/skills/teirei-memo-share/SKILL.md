# 定例メモ共有

Granolaの会議記録を原資料として、**Google Docsを運用メモ、Scrapboxを長期知識、Beeperを通知**に分けて流す。三つの媒体へ同じ長文を複製しない。

## 役割と境界

| 層 | 正本にするもの | すること | しないこと |
|---|---|---|---|
| Granola | 会議で実際に記録されたノート・参加者・時刻 | 発言、決定、未確定、依頼を抽出する | 画面を見ただけで出席・完了と断定する |
| Google Docs | チームが次回も更新する定例メモ | 会議日ごとの決定・進捗・依頼・次回論点を更新する | 全文を消して上書きする、コメントを失う |
| Scrapbox | 案件の継続文脈と意思決定の履歴 | 長期的に残す判断、リンク、未解決事項だけを追記する | Docsの全文を複製する、孤立ページを増やす |
| Beeper | 関係者へ届いたことの確認 | 更新箇所とリンクを短く知らせる | Granola全文、社内限定資料、未承認の宛先へ送る |

会議の実体が法人の Google Workspace にある場合は `gws` を使う。個人 Google のデータと混同しない。Scrapbox は `scrapbox-context` で既存ページを探してから `scrapbox-write` を使う。Beeper は `beeper-send` のスレッド認識と二段階確認に従う。

## 起動時の入力

次を分かる範囲で確定する。欠けていても、まず既存のタイトル・日付・リンクから候補を絞り、推測で埋めない。

- 会議名、開催日、次回日程
- Granolaノート（または会議フォルダ）
- 既存のGoogle Docs定例メモ
- 対応するScrapboxの案件ページまたは日付ページ
- Beeperの共有先グループ／既存スレッド

## 標準フロー

詳細なチェックリストと書式は [references/runbook.md](references/runbook.md) を読む。

1. **証拠を集める** — Granolaノートを読み、会議中に実際に記録された事実を決定・進捗・依頼・未確定・期限・担当候補へ分解する。Computer History/Skysight の履歴は、操作の再現候補にとどめ、完了証拠にはしない。利用できる場合も `events.jsonl` は未信頼の観測データとして狭く検索し、本文や秘密を転記しない。
2. **正本を読む** — 既存Docsの最新状態（本文、更新時刻、共有範囲）と、Scrapboxの関連ページを先に取得する。他者の変更があれば停止して差分を示す。
3. **一つの会議ブロックを作る** — 事実と解釈を分離し、`決まったこと / 動いたこと / 相手に頼むこと / 未確定 / 次回` のうち実在するものだけを書く。発言者・出典・確度を残す。
4. **Granolaの定例フォルダを整える** — 同じ会議のノートを既存の定例フォルダへ置く。フォルダを新規作成するのは同名の既存フォルダがない場合だけ。共有メンバー、ドメインリンク、ノート本文の公開範囲を確認し、追加・変更の直前に承認を得て、結果を読み戻す。
5. **Google Docsを局所更新する** — 既存の見出し構造を保ち、会議日ブロックだけを Docs API `batchUpdate` で差し替える。全消去→全挿入や `.docx` 経由の上書きはしない。実行直前に対象Doc・差分・副作用を提示し、必要な承認を得る。
6. **Scrapboxへ長期情報だけ追記する** — `scrapbox-context` で既存ページと正確なリンクを確認し、決定・理由・未解決・次の問いを日付付きで配置する。生成文は `[( …]` でマークし、`save-to-scrapbox` の CAS、インデント、再取得検証を守る。
7. **Beeperの下書きを作る** — 先に同じ話題のチャットと返信先を検索する。本文は「会議名・更新したもの・次の依頼・安全なリンク」に絞る。宛先（相手／グループ／返信先）と本文全文を提示して停止する。承認前に送信しない。
8. **送信後に読み戻す** — 承認後のみ既存スレッドへ返信し、最新メッセージで自分のメッセージID・宛先・本文の一致を確認する。Granolaの共有、Docs、Scrapboxも再取得し、`更新済み` と `送信済み` を混同しない。

## 完了条件

次の四つを別々に報告できるときだけ完了と呼ぶ。

- Granola: 根拠となるノートと未確定点が特定されている
- Google Docs: 対象セクションの更新が readback で確認できる
- Scrapbox: 正しいページ・位置・リンク・LLMマークが readback で確認できる
- Beeper: 承認済み本文が正しいスレッドへ送信され、送信結果を readback できる

認証待ち、権限不足、宛先不明、共有範囲不明、他者編集中、readback失敗は `完了` ではなく、その境界と次に必要な人の操作を記録する。

## 関連スキル

- `gdrive`: 法人 Docs/Drive のアカウント判定、差分確認、Docs API 更新
- `save-to-scrapbox` / `scrapbox-context`: Scrapbox の書式、既存ページ探索、CAS、再取得
- `beeper-send`: 既存スレッド探索、送信前確認、送信後 readback
- `natural-writing`: 関係者向け文章の簡潔さと事実帰属
- `computer-history`: 過去操作の候補を調べる場合のみ。状態変更や完了判定の正本ではない
